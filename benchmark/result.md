# Benchmark: Redis-k02 single-thread vs multithread

Generated by `benchmark/run.sh` on 2026-11-22 23:42 (took 6 min).

- **Machine:** 11th Gen Intel(R) Core(TM) i5-1135G7 @ 2.40GHz, 8 CPUs, Linux 6.18.58.1-microsoft-standard-WSL2
- **Load generator:** memtier_benchmark 2.6.1, on the same machine, so it competes with the server for CPU.
- **Our server** on port 4000: single-thread, and multithread (io handlers=4, workers=4). MaxKeys = 1000000.
- Each scenario ran **3 times per server**, alternating single-thread and multithread, one server at a time. The table shows the run with the **median throughput**; all its numbers (throughput and latency) come from that one run.
- **Bold** = the better of the two in each column (higher throughput, lower latency).

## 1. Light workload: 50 clients

1,000,000 requests, **80% GET / 20% SET** mixed, from **50 clients** (1 client thread), on random keys out of 100,000. All keys are written once beforehand, so GETs hit. Values are 32 bytes.

```
memtier_benchmark -p 4000 -t 4 -c 25 --ratio=1:0 --key-pattern=P:P --key-minimum=1 --key-maximum=100000 -n allkeys -d 32   # prefill
memtier_benchmark -p 4000 -t 1 -c 50 -n 20000 --ratio=1:4 --key-pattern=R:R --key-minimum=1 --key-maximum=100000 -d 32
```

| | Throughput (ops/sec) | Mean latency (ms) | p50 latency (ms) | p99 latency (ms) | p99.9 latency (ms) |
|---|---:|---:|---:|---:|---:|
| Single-thread | **94,720** | **0.578** | **0.455** | **2.623** | 10.623 |
| Multithread | 44,885 | 1.112 | 1.023 | 2.863 | **5.279** |
